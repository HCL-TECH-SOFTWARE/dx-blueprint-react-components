# Apply updates from a Cumulative Fix (CF)

This guide provides instruction on how to properly update customized Blueprint assets with changes from a Cumulative Fix (CF).
</header>

## Introduction

This document provides a documented process for properly updating customized copies of HCL Digital Experience (DX) Blueprint assets after a Cumulative Fix (CF) has been applied. This guide is for administrators and developers who have implemented custom versions of the Blueprint design system and need to merge new fixes and features from a CF without overwriting their existing customizations.

A Cumulative Fix (CF) may introduce updates to any of the out-of-the-box(OOB) Blueprint assets. Upgrading your HCL DX environment with a CF will overwrite all of the OOB assets but it does not automatically update your customized assets.
This guide provides options for a controlled merge of these changes, rather than a full replacement of your custom code.

## Configuring Blueprint Design System Updates
This section explains how you can control whether certain components of the Blueprint Design System bundle are updated during CF Upgrades. By adjusting the provided deployment configurations, you can choose to keep the existing deployed assets unchanged or allow them to be updated automatically as part of the upgrade process. This gives you granular control over whether the Blueprint Assets and the Nex Haven sample site are updated during a CF upgrade or left unchanged.

### Helm Chart Values — Containerized DX Deployments

For containerized HCL DX deployments, the Blueprint Design System’s updates are managed by configuring the [Blueprint Design System's Helm chart values](/docs/foundations-deployment-configuration--documentation#helm-chart-values).

Add Blueprint Design System's Helm chart values under `incubator.configuration` as shown below:
```
incubator:
  configuration:
    blueprint:
        skipAssetsUpdate: true
        skipNexHavenUpdate: true
```
**Note:** *Set their values to true or false, [based on the update behavior you want to enforce](/docs/foundations-deployment-configuration--documentation#helm-chart-values-descriptions)*

After configuring the necessary Blueprint Design System's Helm chart values, perform a Helm upgrade. The system will then respect the values you set and either apply or skip updates for the Blueprint Assets or the Nex Haven sample site.

### Resource Environment Provider (REP) Properties — Traditional DX Deployment

For Traditional DX Deployment, the Blueprint Design System’s updates are managed by configuring its [Blueprint Design System’s REP properties](/docs/foundations-deployment-configuration--documentation#resource-environment-provider-rep-properties--traditional-dx-deployment).

To configure the REP properties for the Blueprint Design System, follow the [standard process for managing Resource Environment Providers](https://help.hcl-software.com/digital-experience/9.5/latest/deployment/manage/config_portal_behavior/service_config_properties/)

To skip or apply the Blueprint Design System updates, update existing properties or create the required ones (`blueprint.skip.assets.update` and `blueprint.skip.nex.haven.update
`) in WP ConfigService and set their values to true or false, [based on the update behavior you want to enforce](/docs/foundations-deployment-configuration--documentation#resource-environment-providers-rep-properties-descriptions).

After configuring the necessary Blueprint REP properties, perform a CF Upgrade. The system will then respect the values you set and either apply or skip updates for the Blueprint Assets or the Nex Haven sample site.

## General Steps to Follow:

In general, regardless of the updates coming from a CF, the following steps should be followed:
1. **Review the [changelogs](?path=/docs/overview-changelog--documentation).** Understand what changes are included in the CF, specifically which Blueprint assets (WCM items, theme files, Site Builder templates, etc.) have been updated.
2. **Identify the updates relevant to your usage:** Determine which of these updates are relevant to your customized version and need to be merged. Some updates may not be applicable to your customizations (e.g. changes to the sample site).
3. **Backup Your customized assets:** Before applying any updates, ensure you have a complete backup of your customized Blueprint assets (WCM components, theme files, Site Builder templates, etc.). Ensure that all customizations are outside of the OOB Blueprint assets to prevent overwriting during an upgrade.
4. **Upgrade HCL DX**: Apply the CF to your HCL DX environment.
4. **Apply the updates:** The process for applying updates will vary based on the type of asset being updated. Follow the specific instructions for each asset type below. Use projects to manage your changes where possible.
5. **Test thoroughly:** After merging the updates, thoroughly test your customized assets to ensure they function correctly and that both the new CF fixes and your original customizations are working as intended.

## WCM Items

Adopting changes from a new/updated set of OOB Blueprint WCM items into your established customized versions of those items can be a complex task. Picking which changes to adopt has to be purposeful and well-considered. Applying the updates has to be done carefully to avoid disrupting existing customizations. The process will vary based on the type of WCM item being updated (e.g., components, templates). Below are general guidelines for different types of WCM items:

### Content Templates

1. Inspect the updated OOB content templates to understand what changes have been made.
    * Ideally, the updates to the dxcomponent (DXComponent) content template should be merged to their customized conterparts. Changes to this template would likely be relevant to other updates to the Blueprint Design System.
    * Updates to other content templates may or may not be relevant to your own content templates. For example, changes to the Countdown content template may not be relevant to your own content templates.
1. Merge the updates between the latest OOB content templates and the customized ones.
    * If the customizations number more than the number of changes to the OOB template, manually copy the changes from the updated OOB template to your own customized version. Otherwise, make a copy of the updated OOB template and then re-apply your customizations to the new template.
    * Also consider the amount of content items that use the template. Making a new copy of the template will also entail changing all of the content items using the old template to use the updated template. At the moment, there is not an automated way to do this in bulk that is built into HCL DX, however it can be done through scripting and the use of the HCL DX WCM v2 APIs.
2. Apply the updated template to the existing content items.
    * This can be done by starting the application of the template from the content template itself. This will update all content items using that template.
    * This can also be done by starting the application of the template from the content item itself. This will update only that specific content item.
3. If you opted to make a copy or create a new content template, replace the references from the old content template to the updated content template.

### Presentation Templates

1. Inspect the updated OOB presentation templates to understand what changes have been made.
    * Ideally, the updates to the dxcomponent (DXComponent) presentation template should be merged to their customized counterparts. Changes to this template would likely be relevant to other updates to the Blueprint Design System.
    * Updates to other presentation templates may or may not be relevant to your own presentation templates. For example, changes to the Event presentation template may not be relevant to your own presentation templates.
2. Merge the updates between the latest OOB presentation templates and the customized ones.
    * If you did not make any customizations to your copy of the OOB presentation template, you can simple copy/export the markup of the updated OOB presentation template and paste/import it into your own copy.
    * Otherwise, manually copy the changes from the updated OOB template to your own customized version.

### Content Items

1. Inspect the updated OOB content items to understand what changes have been made.
    * Changes to the Nex Haven site content items may not be relevant to your own content items.
    * Changes to the page components (i.e. items in the Blueprint Design System library) may be relevant to your own page components.
2. Merge the updates between the latest OOB page components and the customized ones.
    * If the changes were brought about by an update on the content template that the content item is based on, then applying the updated content template to the content item should bring in those changes.
    * If the changes were applied directly to the elements or properties of the content item, then manually copy the changes from the updated OOB content item to your own customized version.

### Site Areas

1. Inspect the updated OOB site areas to understand what changes have been made. Changes to the Nex Haven site areas are likely not be relevant to your own site areas since they are either only used to organize the Blueprint page components or are specific to the sample site.
2. If there are any changes to the site areas that you want to adopt, manually copy the changes from the updated OOB site area to your own customized version.

### HTML Components

1. Inspect the updated OOB HTML components to understand what changes have been made.
    * Changes to the Nex Haven site HTML components may not be relevant to your own HTML components.
    * Changes to the HTML components in the Blueprint Design System library may be relevant to your own HTML components.
2. Merge the updates between the latest OOB HTML components and the customized ones.
    * If you did not make any customizations to your copy of the OOB HTML component, you can simple copy/export the markup of the updated OOB HTML component and paste/import it into your own copy.
    * Otherwise, manually copy the changes from the updated OOB HTML component to your own customized version.
    
## Theme

To properly update your customized theme files (CSS, JavaScript, JSPs) with changes from a Cumulative Fix (CF), follow these steps:

1. Inspect the updated theme files and identify which updates you need or want to adopt. Refer to the change to find out which specific theme files (e.g., `style.css`, `script.js`, `nav.jsp`) have been updated.
    <Admonition type="tip">
    Use a file comparison tool (e.g., `git diff`, WinMerge) to compare the new CF version of the files with your customized versions.
    </Admonition>
2. Manually merge the changes. Take care to preserve your customizations while integrating the new updates.
3. Validate the Code. After merging the changes, ensure your custom code still functions correctly and does not conflict with the newly merged CF updates.
4. Test the updated theme to confirm that the new CF fixes and features are working as intended and that your custom design and functionality remain intact.

## Page Templates

When a Cumulative Fix (CF) includes updates to the OOB page templates, you simply have to copy the updated OOB template and manually re-apply your customizations to the new template. After doing this, you can then use the updated template when creating new pages. If you wish to apply the changes to existing pages, you have to recreate the pages using the updated template or manually adjust the existing pages to reflect the changes.

## Site Builder Templates

Changes to the OOB Site Builder templates are not typically something you would want to merge into your own templates, as they are often specific to the sample site.
